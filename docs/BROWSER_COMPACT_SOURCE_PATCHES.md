# Compact source edits in the browser

The existing browser source editor now encodes complete-file replacement intents
as bounded, byte-exact contextual hunks. Queueing and `SourceEditClient.prepareEdits`
both use the shared encoder; no new endpoint, runtime dependency or alternate
publication path is introduced. Raw-patch upload remains a separate existing path.

## What changes

Unchanged leading and trailing lines are omitted, retaining up to three context
lines at each edge. A bounded Myers search separates distant edits into multiple
hunks. Touching context is coalesced, and every hunk carries exact old and new line
positions, including cumulative insertions and deletions. There is no fuzzy
application, three-way merge, rename inference or decoded-text substitution.

Line identity includes every byte: CRLF, invalid UTF-8, NUL under the existing
explicit binary profile, and the presence or absence of a final newline. Mode
changes, raw byte paths and empty-file creation/deletion remain supported. Short
single-hunk replacements retain their earlier bytes when no substantial unchanged
region can be omitted. Initial file creation and deletion still carry all content.

Complete before/after bytes and modes remain in the returned normalized edit set.
The source client still hashes those complete effects, checks native preparation
against them, and inspects the candidate before staging publication. Changing the
encoder never reconstructs a saved candidate or the bytes/key of a pending request.
Existing exported receipts still recover or resend their exact original request.
These are encoding changes, not new authority or relaxed candidate verification.

## Separate bounds

The encoder permits at most 64 file effects, 256 KiB per file, 4 MiB of aggregate
retained before/after bytes and 65,536 aggregate input lines. The final encoded
patch remains limited to **1 MiB**. A rename still consumes two disjoint effects.
The existing project-picker import preflight retains its conservative 1 MiB
aggregate bound; this change does not broaden that separate import interface.

The line search has edit-distance ceiling 64, at most 262,144 search/comparison
steps and 32 MiB of candidate line-comparison bytes shared across the entire
sorted edit set. Trace allocation is bounded to 65 small frontiers. Prefix/suffix
scans and line-offset construction are linear in already-bounded input. No
quadratic input-sized table or unbounded recursion is allocated.

If the bounded search cannot finish, the encoder retains the entire exact changed
middle rather than returning a partial diff. Encoding may then reach the unchanged
patch ceiling and refuse. It never omits an intended edit to fit a budget. This is
not a guarantee of minimal patches or arbitrary-size source editing.

The regression fixture of eight 256 KiB files, each with two distant byte changes,
retains 4 MiB of complete verification input but produces a 9,128-byte, 16-hunk
patch. Both forward and reverse application reproduce independently built native
Git trees in SHA-1 and SHA-256 test repositories.

## Reproduce the focused checks

```sh
node --test tests/browser/source-edit-compact.test.mjs \
  tests/browser/source-edit-compact-browser.test.mjs
```

The main lane imports the production encoder and uses installed Git only as a
test oracle. It also applies 2,000 deterministic generated byte-level edit cases
with an independent strict interpreter that cannot relocate a hunk. Cases include
insert/delete offsets, repeated lines, raw paths, binary payloads, EOF markers,
executable modes, renames, capacity boundaries and bounded-search exhaustion.

The Chromium lane executes the same production module bodies and helper offline,
rewriting only their import URL to a data URL. It compares returned patch bytes
with Node execution; it does not navigate an HTTP forge, simulate a DOM or claim
authenticated publication. Set `FG_TEST_CHROMIUM` to select a Chromium executable;
that lane explicitly skips when Chromium is not installed.

Local validation used Node 22.16.0, Git 2.47.3 and Chromium 144.0.7559.96. This is
not a Rust compile, native `fg` admission/CAS test, complete UI flow, pinned Git
conformance gate, power-loss test or full-workspace pass. The larger source
editing and bridge-product work remains partial.
