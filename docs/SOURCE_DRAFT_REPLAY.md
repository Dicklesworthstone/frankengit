# Replay a reviewed source draft onto a separately selected commit

When another writer changes a branch, an old source draft must not quietly take
that branch's new base. `replaySourceChanges` in `scripts/operator/source_replay.mjs`
provides an explicit offline alternative: supply the original package, independent
expectation, changes and reviewed draft hash, plus another package and a separately
chosen expectation. It either constructs a new standard authoring draft with the
same exact patch, or refuses the replay. No branch, credential, candidate, staged
journal, idempotency key or network operation enters this API.

This is an external source-authoring operation, not native Git history rebase,
three-way textual merge, a semantic merge proof or a mutation retry. The source
packages prove native commit/tree/blob commitments, not repository ownership,
branch freshness or ancestry between the selected commits. Unrelated commits are
not labelled as ancestors or descendants by this operation. A team can use it
when a separately observed branch has advanced, but must select and verify its
publication target independently through the existing preparation/staging APIs.

## Exact replay contract

The original draft is regenerated by the complete existing authoring kernel and
must match the operator's reviewed hash. Both source packages, both expectations
and all changes are copied under the shared finite input grammar before the first
asynchronous digest. One monotonic deadline spans both verifications.

The next commit must differ and use the same native hash domain. Its independently
selected file set must exactly equal the original selected file set: same byte
paths, native blob IDs and verified regular/executable modes. This includes
unchanged context files, paths whose edits became no-ops, and read-only copy
sources. Narrowing or widening the selection is not accepted as an equivalent
review. A changed selected input needs a newly authored/reviewed change instead.

The kernel regenerates the same explicit edits against the verified new source.
Every creation/relocation destination must still be proved absent. An omitted
subtree is never absence and is never fetched automatically. If an originally
absent directory now exists but is not in the proof, replay refuses rather than
assuming its children are empty. Already-applied edits are not silently removed
or reported as completed repository transactions.

Patch bytes, all changed path before/after identities and modes, no-op paths and
explicit relocation records must remain identical. Only then is the new draft
returned. The original commitment, new commitment, reviewed hash, new draft hash,
source/expectation hashes and both independently calculated expected trees are
bound into a reproducible replay receipt. Unchanged new-base entries/subtree IDs
are retained by the existing whole-tree calculator.

The new draft hash is different because its selected source is different. **Review
and explicitly confirm that new hash** before preparing/staging a new candidate.
Original publication consent does not carry over. An existing journal is never
retargeted: resolve an uncertain original publication with its original key before
considering a separate change. This operation cannot determine whether a caller
has an unresolved journal elsewhere.

## Library use and limits

```js
import { replaySourceChanges } from './scripts/operator/source_replay.mjs';

const replay = await replaySourceChanges(
  originalPackageBytes, originalIndependentExpectation, originalChanges,
  nextPackageBytes, nextIndependentExpectation,
  { confirmDraftSha256: reviewedOriginalDraftHash, timeoutMs: 30000 },
);
// replay.next: owned normalized inputs for the existing authoring consumer.
// replay.draft: the new standard { bytes, manifest, tree } draft.
// replay.receipt: old/new binding with new_review_required: true.
```

Each package retains the existing 32 MiB encoded, 8 MiB logical source, 32 selected
file, 128 proved parent-tree and 4 MiB tree-byte ceilings. The two packages are
separately owned, so encoded inputs can total 64 MiB. Each generation uses the
existing 32-effect, 1 MiB file/patch and 4 MiB retained before/after authoring
bounds. `limits` may narrow those edit bounds; it cannot widen them. `timeoutMs`
is 1..300000 (default 30000); `signal` is an optional AbortSignal. Unsupported
binary edits and source proof cases remain the shared kernel's typed refusals.
No partial new draft is returned on cancellation, a conflict or a hash mismatch.

Run `bash scripts/verify_source_replay.sh`. The core tests use independently
framed native objects, both hash domains, changed and preserved read-set twins,
all supported edit operations, malformed proofs, exact bounds, caller mutation,
and cancellation. They include a changed file where naive replace-once still
succeeds, and a changed unused executable mode where the patch remains identical;
both are refused by the original read-set checks. This is not native Rust
TreeFS/admission/CAS, semantic compatibility or whole-workspace evidence.
