# Accumulated source context from a retained session prefix

The consumer is an operator or agent that has run several explicit searches in
one durable context session and needs the accumulated excerpts without copying
files and reconciling repeated bytes by hand. `assembleSessionContext` reuses the
existing session replay and capture validators. It produces one deduplicated
source view; it does not query a server, reserve work, refund earlier reads,
advance session state, or manufacture an Agent Protocol ContextPacket.

## Operator workflow

Keep the session root hash and the desired terminal tip independently. Export
all successful captures through exactly that tip into a new private directory:

```bash
node scripts/fg_context_session.mjs export \
  --session /private/context/session \
  --session-sha256 "$SESSION_SHA256" \
  --tip-sha256 "$RETAINED_TIP_SHA256" \
  --output /private/context/accumulated
```

The output contains `context.json`, quoted `context.txt`, and a last-written
`manifest.json`. Retain the returned `manifest_sha256` independently. Inspect
by replaying the same session prefix and comparing the exact regenerated bytes:

```bash
node scripts/fg_context_session.mjs inspect-export \
  --session /private/context/session \
  --session-sha256 "$SESSION_SHA256" \
  --tip-sha256 "$RETAINED_TIP_SHA256" \
  --output /private/context/accumulated \
  --export-sha256 "$EXPORT_MANIFEST_SHA256"
```

Both commands are offline and accept no credential, CA, or endpoint override.
They require the original session and its referenced prefix captures; this is
not a self-contained native source proof or an alternative session backup.
Existing `init`, `step`, `dispatch`, `status`, and `recover` behavior is unchanged.

## Exact prefix, not an inferred latest state

The selected tip must be the session root (base capture only) or an exact
validated terminal in its history. A request hash or unacknowledged candidate is
not a terminal tip. Replay verifies the complete chain, requests, reservations,
and successful capture bytes through the selected terminal. The merger receives
those same validated captures, never files reopened after an inspection check.

A later successful, refused, or interrupted operation is not included. Later
step payloads are not examined; directory-name bounds are still checked while
locating a non-base tip. An old export remains byte-identical after subsequent
queries and remains inspectable when a later payload is corrupt. Ordinary
`status` and all mutating session operations still check the full current ledger;
prefix selection is an explicit read-only export facility, not weaker recovery.

The result labels `selected_terminal_prefix_only` and `later_steps_not_examined`.
`reserved_at_tip` means reservations in that historical prefix, not currently
available budget. Failed reads remain in its immutable history and accounting
without contributing fabricated excerpts. No export adjusts the real ledger.

## Merge semantics and provenance

The base and every captured step must share the exact canonical source tuple:
tenant, repository, incarnation, native object format, reference, source head,
repository commit record, source commit and root tree. A given raw path must
also retain one blob identity and source size. Different index generations at
that same source are allowed and are retained separately for each query.

All captured files are included in raw-path order. The algorithm merges touching
or overlapping excerpt ranges only when every overlapping byte agrees. Holes
remain holes, binary bytes remain lossless hex, CRLF is unchanged, and an empty
path-only file retains its empty range. Repeated files and anchors retain every
contributing query sequence. Path-match offsets stay path coordinates; content
and symbol anchors stay file coordinates. Each merged range records the source
query/range contributions. Equal blobs at different paths are not conflated.

If the union of fragments covers the entire file, its native SHA-1 or SHA-256
Git blob identity is verified even when no individual capture included the full
body. This checks bytes against the claimed blob, not membership at a path in an
independently chosen commit. Partial unions do not receive a full-blob hash claim.
Conflicting overlaps or false full blobs reject the whole export, not just the
problematic range, and there is no fallback file or preferred-query winner.

Each query keeps its original terms, scopes, symbol policy, generation and
checkpoint observations, ranking receipt, coverage omissions, retrieval
truncation and hydration omissions. The export does not recompute cross-query
ranking or turn several incomplete queries into a complete repository inventory.
`all_captured_queries_complete` is a conjunction of their individual completion
flags, not global coverage. There is deliberately no aggregate `complete` field.

**Earlier captures may have broader scopes than later narrowed follow-ups.**
The accumulated view intentionally includes that previously captured data under
its original per-query scope; it must not be passed off as a result authorized by
only the latest narrowed query. Offline replay rechecks no current repository
permissions, freshness or revocation. Keep the export owner-private and obtain
separate authorization before sharing it. Source and query text remains quoted
untrusted data, never instructions, credentials or capability material.

## Limits, publication and failure

An optional private `--export-limits-file` may narrow these independent export
ceilings (unknown keys or larger values refuse):

```json
{"max_files":32,"max_excerpt_bytes":1048576,"max_metadata_bytes":1048576,"max_output_bytes":8388608}
```

Hard ceilings are 544 unique files, 17 MiB of unique excerpt bytes, 8 MiB of query
metadata, and 48 MiB for each encoded output. Inputs are bounded to the session's
base plus 16 positions, 2,176 excerpt windows and 69,632 anchor occurrences.
Insufficient limits reject before creating the export directory; they never
silently evict earlier context or clip evidence. This is buffered, bounded replay
and merging, not constant-time or streaming processing. Its configured limits
are not cumulative query quotas; the original session reservations remain intact.

Paths must be normalized absolute paths with owner-private 0700 directories and
0600 regular single-link payload files. The output must be absent and outside the
source session. Existing destinations and competing exporters are not overwritten.
All content and hashes are computed before publication. Once the directory is
claimed, writes, file/directory syncs and exact readback drain despite a late
cancellation. The complete manifest is written last. Failure after the claim
retains the prospective output path and hashes as explicitly unconfirmed; it
never removes a partial export to make a retry succeed. A confirmed result whose
stdout fails is returned in `retained_result` diagnostics when stderr is usable.

Inspection requires the independently retained manifest hash and repeats session
replay plus semantic validation, then compares the canonical manifest and both
payloads byte-for-byte. Rewriting local payload hashes cannot legitimize a changed
projection. Retain the source session for this replay; hashes alone are not
repository authority, freshness evidence, or a signature.

All commands accept `--timeout-ms` from 1 to 300000 (default 30000). One deadline
covers pre-publication work. Submitted filesystem calls are awaited; JavaScript
hashing/encoding is checked at bounded checkpoints, not interrupted mid-operation.
This is a trusted owner-private POSIX custody profile, not hostile-parent
confinement, a distributed lock, or a universal hardware power-loss guarantee.

Exit 0 means an export/inspection whose captured queries were individually
complete and whose selected history has no refused step. Exit 3 retains explicit
partial/refused-query evidence. Exit 2 means refusal before publication; exit 4
means a committed result lost output or publication requires inspection using
the retained path/hash. Neither success code claims global search completeness.

## Library and verification

```js
import { assembleSessionContext } from './scripts/operator/source_context_session.mjs';
import { exportSessionContext, inspectSessionContextExport }
  from './scripts/operator/source_context_session_export.mjs';

const material = await assembleSessionContext(session, rootHash, tipHash, limits, { signal });
const receipt = await exportSessionContext(session, rootHash, tipHash, output, limits, { signal });
const checked = await inspectSessionContextExport(session, rootHash, tipHash,
  output, receipt.manifest_sha256, { signal });
```

`mergeContextExcerpts` is a pure kernel for already validated loader projections,
not a replacement for native-response or session validation. Product consumers
use the session APIs above. No new server session, mutation route, production
dependency or Rust implementation is introduced.

```bash
bash scripts/verify_source_context_session_export.sh
```

The focused tests import complete production modules and execute real private
files, CLI child processes and HTTP sockets for setting up captured sessions.
Peers are explicit native-schema fixtures, not a Rust server. Cases cover both
Git formats, per-query evidence and full-width generation numbers, overlap and
collective blob-hash conflicts, historical tips, candidate exclusion, budget
boundaries, corrupted selected/later records, concurrent exports, cancellation,
lost output and offline regeneration. Native interoperability, full session and
client suites, real-browser runs and workspace verification remain separate.
FG-032 and concrete Agent Protocol adoption remain open.
