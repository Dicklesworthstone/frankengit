# Initial commits through MCP

The source-candidate tool's `prepare_initial` operation constructs the first
commit of an absent branch, including an empty repository. It uses the native
creation-only planner and full-bundle writer, not a synthetic parent or a Git
subprocess. It is part of the trusted-local sponsored MCP profile (FG-096,
x2mv.4.24), not remote IAM or automatic agent authorization.

Supply `operation: "prepare_initial"`, exactly one of `reference` and
`reference_hex`, exactly one of `patch` and `patch_hex_chunks`, and explicit
`author`, `committer`, `timestamp` and `message_hex`. These byte/metadata fields
have the same validation as `prepare_patch`. The patch must only create regular
files. `expected_head` optionally pins the canonical selection. `expected_base`,
principal, force and publication-key fields are rejected, not ignored.

Only `--allow-source` grants preparation. The native selector requires the
branch to be absent and visible under the selected hidden-ref policy. Other
branches may exist; their histories and the default HEAD are not changed.
Preparation stages no objects, seals, refs, forge records or retry state.

The result contains a real selecting `snapshot_token`, zero parents, null
`source_commit`, the full native commit body, and every new file's exact bytes,
path, mode and blob identity. Inspect these generated bytes, not just the patch.
The preview covers the entire initial tree. It is construction evidence, not
an independent inspection of an arbitrary uploaded bundle or an approval.

Preparation returns at most 64 files, 128 KiB of preview bytes (including paths
and commit metadata), and a complete full bundle in at most three 8 KiB hex
chunks. Native work, expansion and request budgets still apply. Oversized
results fail rather than exposing a partial publishable candidate. No host
path or URL is accepted as a source of bytes.

`publication_arguments` names `frankengit_source_publish` with `initial: true`,
an exact candidate, branch and full bundle. It deliberately contains no retry
key. The initial-publication adapter must be installed before submitting this
shape; legacy publishers reject it. Publication requires the independent
source-write grant and the caller's own original idempotency key. A preparation
snapshot never reserves branch absence or bypasses later admission policy.

Parser, exact-byte preview and persisted SHA-1/SHA-256 MCP tests accompany the
implementation. The implementation environment has no Rust toolchain or built
`fg`; authored tests are not a passing native-test or agent-day claim.
