Cherry-pick and revert

Source · History and blame · Branches · Source editor

Apply or undo one exact commit on a selected destination branch. Preparation and inspection never publish. Native permissions, branch protection, and conditional publication remain in charge.

Select one immutable snapshot



For a revert on the same branch, use that branch for both fields. Credentials remain in page memory; HTTPS is required outside loopback. A known object ID alone does not grant access to its history.


Choose the exact change











Merge commits require an explicitly chosen parent number. The new commit has the destination tip as its only parent. Author text is not authenticated identity or a signature.


Resolve reported conflicts


No resolution is selected by default. During a revert, “theirs” is the selected parent (the undo side), not the source branch tip. An absent side never implies deletion. Custom files allow exact binary bytes, at most 256 KiB each and 1 MiB combined.




Inspect the complete changed-path report


Text previews have a combined 256 KiB display limit. Binary and opaque content are identified, not rendered as source. Inspect the native candidate before preparing publication.




Publish or recover the original request






A timeout or disconnected reply never proves rollback. Preserve the original key; do not prepare a replacement transaction. Recovery files contain repository bytes and must be protected. Their checksums are not signatures.
