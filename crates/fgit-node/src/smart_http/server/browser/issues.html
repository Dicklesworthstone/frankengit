Repository issues

Read issue history at one snapshot. Prepare comments and assignee additions independently, or name an exact previous version for other changes. The canonical admission service publishes every change.

Independent grants: issues-read to browse, issues-write to change, outcomes-read to recover. No token is stored in a URL, file, cookie, or browser storage.

Connect an explicitly scoped repository token.

Find and triage issues

Filters combine with AND. Labels are exact; text matches title or body, not comments. Case-insensitive text folds ASCII only. Empty scan-limited pages may still have candidates to examine. Continuations keep the applied filters and original snapshot even when these fields change.

Prepare an issue change

Choose an explicit issue number and version 0 to open a new issue. Comments, label additions, and assignee additions need no expected version, so other people can update the issue while you prepare them. Locked discussions refuse comments until unlocked; label and assignee additions remain available. Editing fields, removing assignees, closing, reopening, locking, and unlocking require the exact issue version. Locking is independent of whether the issue is open or closed.

Title (256 UTF-8 bytes maximum)
Body or comment (64 KiB maximum)
Labels (one per line; at most 32, each 64 UTF-8 bytes)
Principal IDs (one per line; 1–16 IDs)

Each ID is 32 lowercase hexadecimal characters. Add or remove only these people; other assignments stay. Assigning an issue does not grant repository access.

Select an open milestone

Open the issue and choose Set or move milestone. Load milestones from that same snapshot, then select one. Preparation pins both observed versions; a concurrent edit or close can refuse the change. Closed or locked issues can still move between milestones.

Save the recovery receipt before sending. It contains private draft text and a retry key, but no token. A timeout or missing lookup result never proves that a change was not committed. Reloading this page loses its in-memory request unless you saved the receipt.

      

    

    
Restore an unresolved request

      
Connect the original credential, then load its saved receipt. Restoring never sends a change. Keep that credential bound to the same principal; this browser cannot authenticate an operator’s reassignment of a token.
