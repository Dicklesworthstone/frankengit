Repository issues

Read issue history at one snapshot. Every change names an exact previous version and is published only by the existing canonical admission service.

Independent grants: issues-read to browse, issues-write to change, outcomes-read to recover. No token is stored in a URL, file, cookie, or browser storage.

Connect an explicitly scoped repository token.

Find and triage issues

Filters combine with AND. Labels are exact; text matches title or body, not comments. Case-insensitive text folds ASCII only. Empty scan-limited pages may still have candidates to examine. Continuations keep the applied filters and original snapshot even when these fields change.

Prepare a version-checked change

New issue numbers are explicit, not guessed from a page. Choose open with version 0 for a new issue. Existing issues require their exact version; reopening or editing never bypasses a conflict.

Title (256 UTF-8 bytes maximum)
Body or comment (64 KiB maximum)
Labels (one per line; at most 32, each 64 UTF-8 bytes)

Connect the original credential, then load its saved receipt. Restoring never sends a change. Keep that credential bound to the same principal; this browser cannot authenticate an operator’s reassignment of a token.
