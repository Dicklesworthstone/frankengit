1. Repository credential

Preparation requires source read. Publication requires the independent receive grant and operator Git-write enablement. Recovery requires outcomes-read. Tokens stay in page memory.

2. Destination

A missing or hidden branch read does not establish absence. The native publisher checks absence atomically. The optional snapshot is a preparation check, not a publication lease.

3. Initial files

Uploads preserve exact bytes, including non-UTF-8 and line endings. Binary and NUL-containing files are supported. Empty hex input creates an empty file. Symlinks and gitlinks remain unsupported. Up to 64 files, 256 KiB per file and a 1 MiB generated patch.

Import a project in one batch

Directory import removes only the selected top-level folder name and preserves all nested paths. The optional prefix is added to every destination. No ignore rules or hidden-file exclusions are applied: a selected .git path rejects the entire import. Use a source-only directory. Browser file selection supplies bytes, not original host executable bits, symlink identities, empty directories or Git history. Review the selected mode; change individual files through the editor above. Batch imports never replace a queued path and never retain only a successful prefix. Files and directories share the same 64-file, 256 KiB/file, 1 MiB content and encoded-patch limits. Importing queues bytes locally; it neither creates a repository nor publishes a branch.
