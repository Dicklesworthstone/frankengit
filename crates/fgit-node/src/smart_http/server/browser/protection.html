Administer repository review protection

This independent administration page does not require the pull-request or source-browser profiles. The native protection API authorizes every operation.

Credentials remain in page memory only. HTTPS is required outside trusted loopback. No bootstrap, silent refresh, or automatic retry is performed. Listing an administrator is not proof that the current credential can act as that principal.

Replace the complete native policy

Inspect first. Existing administrators authorize the replacement; the proposed administrator set cannot authorize itself. These controls manage exact branches, eligible reviewers, approval counts, and required workflow checks. Every check must identify its protected branch and the exact CI source, publisher, workflow commitment, and job.

Complete required workflow check set

Each selector requires a successful latest result for the exact proposed commit. Add or edit a selector below, or remove it explicitly. A check can protect a branch without requiring human reviewers.

At most 32 checks per protected branch. Both branch names use exact lowercase hex bytes; publisher IDs use 32 hex digits and workflow commitments use 64. Job names are exact, case-sensitive text up to 1024 UTF-8 bytes; spaces and colons are preserved. The protected branch must also appear in the branch rules above.

One rule per line; at most 64 branches and 32 reviewers per branch. Use a count such as 2 for two approvals from the listed reviewers, or all to require every eligible reviewer. Separate the three fields with spaces. Use - for the reviewer list of a check-only branch and add at least one required check. Removing or renaming a branch rule requires explicitly removing or retargeting its check rows. A branch cannot retain an empty reviewer list after its last check is removed. Native reference bytes are hex so non-UTF-8 names survive editing. Resource refusals never truncate a policy. Every successful replacement advances the policy epoch and invalidates earlier candidate approvals.

Recover an uncertain publication

Disconnect, timeout, missing keys and transport errors do not prove non-commit. Save the original receipt, not a re-created replacement. A rotated credential is outcome-only and must identify the same original principal.

Receipts use the shared protection client format and can move between the PR panel and this page for the exact same origin and repository. They contain policy data and a credential fingerprint, never the bearer token. No automatic retry, save, restore, or publication occurs.
